# Problem
Registry tweaks support revert when removed from config. System settings (brightness, volume, notifications) do not — they stay set permanently.

# Solution
- Added CaptureOriginalSettingsAsync to SystemSettingsService, which reads current brightness and volume before applying new values, so originals can be restored later.
- Added RevertSystemSettingAsync to SystemSettingsService, which restores brightness or volume to their captured original values when a setting is removed from config.
- Updated StateService to use StateData instead of HashSet<string>, adding SystemSettingOriginals dictionary to persist original values across runs.
- Fixed SaveState in StateService to preserve SystemSettingOriginals when saving AppliedItems.
- Updated Engine.RunAsync to capture originals before applying system settings, and revert them when settings are removed from config.yaml.
- Updated Engine.PrintDiffAsync to show system settings reverts in --diff output.
- Added CaptureOriginalSettingsAsync and RevertSystemSettingAsync to ISystemSettingsService interface.
- Switched volume commands from Set-AudioDevice (requires third-party AudioDeviceCmdlets module) to MMDeviceEnumerator COM API which works on any Windows machine without extra dependencies.
- Added backward compatibility in StateService.LoadState to deserialize old HashSet<string> state files
